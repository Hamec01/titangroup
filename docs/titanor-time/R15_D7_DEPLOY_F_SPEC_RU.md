# R15-D7 — Deploy F: отчёт «Часы заказчику» (спецификация)

**Статус:** зафиксировано по STOP-GATE владельца 2026-09-02. **Не реализовывать в Deploy D.**
Реализация — только после Deploy A→E и отдельного подтверждения владельца. Production не менять.

---

## 0. Почему нужен новый отчёт (дефект текущей `/admin/reports/customer`)

Текущая страница **НЕ является** настоящим отчётом по заказчику:

- поле `customer` — **свободный текст**, используется только как заголовок PDF;
- `scope` выбирает `siteIds` и `employeeIds`, **не** `workAreaId`;
- `export` / `getCustomTimeReport` **не фильтрует сегменты по `workAreaId`**;
- на одном объекте бывает несколько заказчиков (`WorkArea`);
- ⇒ **в документ одного заказчика могут попасть часы другого заказчика** на том же объекте.

Deploy F заменяет это настоящим отчётом с фильтрацией по `workAreaId`.

---

## 1. Период
- дата «с»;
- дата «по».

## 2. Настоящий заказчик (не свободный текст)
- выбор **существующего** заказчика из базы (`WorkArea`), не свободный ввод;
- поиск по названию заказчика **и** названию объекта;
- строка результата: **«Aros Marine — Meyer Turku Shipyard»** (заказчик — объект);
- разрешить выбрать **одного или нескольких** заказчиков;
- отдельный вариант **«Без указанного заказчика»** (`workAreaId IS NULL`) — только для внутренних проверок;
- **финальный клиентский PDF нельзя создать без явно выбранного заказчика** (сервер отклоняет).

## 3. Карточка после выбора
```
Заказчик: Aros Marine
Объект: Meyer Turku Shipyard
Сейчас назначено: N работников
Работали за выбранный период: N работников
Всего часов за период: X ч Y мин
```
**Различать явно:**
- «сейчас назначены» (`SiteAssignment` с `workAreaId` = выбранный, операционно-live);
- «имеют часы за выбранный период» (есть `WorkSegment` / committed-строки с `workAreaId` = выбранный и датой в периоде).

Уволенный / переведённый работник **остаётся** в историческом отчёте, если у него были часы этого
заказчика в периоде.

## 4. Список работников
Колонки: ФИО · табельный номер · объект · заказчик · даты работы · часы за период · статус табеля.
- заметная галочка выбора; «Выбрать всех»; повторный клик снимает выбор;
- поиск по имени, номеру, объекту, заказчику;
- 20 работников на страницу; **выбор сохраняется между страницами**.

## 5. Предпросмотр до скачивания
- название заказчика; объект(ы); выбранный период; число работников;
- таблица работников и их часов; общий итог;
- **список неутверждённых табелей со ссылками**.

## 6. Данные (сервер)
- в `scope` / `export` добавить настоящий `workAreaId` / `workAreaIds`;
- **фильтровать `TimesheetDraftSegment` и `WorkSegment` именно по `workAreaId`**;
- `customer name` для PDF/CSV сервер берёт **по выбранному ID**, не доверяя переданному браузером тексту;
- **историческую принадлежность определять по `workAreaId` самого записанного сегмента**, а не по
  сегодняшнему назначению работника;
- readiness (полнота утверждения) считать **только внутри выбранного customer scope**.

## 7. Содержимое PDF и CSV
Заказчик · объект · период · ФИО и номера работников · часы каждого работника · общий итог ·
отметка «данные окончательно утверждены». **Без зарплат, ставок и внутренних данных.**

## 8. Обязательный тест
- на одном объекте **два** заказчика;
- у работника A — часы Aros, у работника B — часы второго заказчика;
- отчёт Aros содержит **только** часы Aros;
- ни UI, ни preview, ни PDF, ни CSV **не показывают** второго заказчика;
- работник, позже переведённый к другому заказчику, **остаётся** в историческом отчёте Aros;
- **inactive** заказчик остаётся доступен для исторического отчёта;
- выбор / reload / Back-Forward / RU-EN / 20+ работников — работают.
