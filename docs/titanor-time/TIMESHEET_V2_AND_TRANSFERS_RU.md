# Табель v2 и перевод работников — правила (решения владельца 2026-10-15)

Документ описывает, как работают `/admin/timesheets-v2` и перевод работника между объектами и заказчиками. Старый «Табель» (`/admin/timesheets`) не изменён и остаётся инструментом для нестандартных случаев.

## 1. Табель v2

**Страницы:**
- `/admin/timesheets-v2` — карточки заказчиков за месяц: заказчик, объект, сколько человек прикреплено и сколько часов набрано за месяц.
- `/admin/timesheets-v2/<объект>/<заказчик|none>?month=YYYY-MM` — таблица за месяц, как в Excel у заказчика: Nr., Фамилия, Имя, Таб. №, дни 1–31, Итого, строка «Сумма:».

**Строки таблицы:** работники, у которых назначение к этому заказчику пересекается с месяцем (`validTo` включительно), плюс все, у кого есть часы у этого заказчика.

**Источник часов:** `getTimeLedger()`, по дням (`DisplayDay`). Это те же недельные срезы, что в «Табеле» и «Сводке». Если день разделён между двумя заказчиками, у каждого заказчика видна его часть.

### 1.1 Часы по графику (правило 1)
- В рабочий день шаблона графика засчитывается только время внутри окна шаблона. Из него вычитаются те же перерывы, что вычитает основной табель.
- Итог дня не больше фактических часов и не больше планового дня (окно минус неоплачиваемый обед).
- Пример для шаблона 07:00–18:00 с неоплачиваемым обедом 30 мин:

| Отработано | Засчитано |
|---|---|
| 06:30–18:30 | **10,5 ч** |
| 09:00–20:00 | 9 ч внутри окна − обед = **8,5 ч** |
| 12:00–18:00 | фактически отработанное (меньше плана) |

- **Выходной по шаблону** (например, воскресенье) и **работник без шаблона** — засчитываются фактические часы.
- Суббота и воскресенье в таблице всегда синие.
- Шаблон берётся из назначения работника к этому заказчику, действующего на эту дату.
- Если часы урезаны по графику, в подсказке ячейки показано «по факту X ч, засчитано по графику».
- Переработку начальник вписывает вручную (правило 2).

Код: `lib/reporting/monthly-matrix.ts` (`capToSchedule`, `dayPlanFor`, `loadMatrixOptions`).

### 1.2 Ручные значения — «Редактировать табель» (правило 2)
- Кнопка рядом с «Показать». В ячейку можно ввести:
  - часы: `10`, `10,5`, `7:30`;
  - `OFF`;
  - пустое значение.
- Стрелки и Enter переводят курсор между ячейками. «Сохранить табель» отправляет только изменённые ячейки.
- Сохранённое значение полностью заменяет рассчитанную ячейку — и на экране, и в Excel. Такие ячейки помечены фиолетовым уголком.
- «Вернуть автоматические значения» удаляет все ручные значения этого заказчика за этот месяц.
- Хранилище: таблица `TimesheetV2CellOverride` (миграция `20261015090000`). Уникальный индекс `NULLS NOT DISTINCT`, чтобы «без заказчика» тоже была одна строка на ячейку.
- Аудит: `TIMESHEET_V2_CELLS_EDITED` (до/после по каждой ячейке), `TIMESHEET_V2_CELLS_RESET`.
- Ручные значения **не меняют** старый табель, утверждения и другие отчёты.
- API: `POST` и `DELETE /api/admin/timesheets-v2/cells`, только для ADMIN и SUPER_ADMIN, с CSRF-заголовком.

### 1.3 Ячейки
- **Зелёная** — есть часы.
- **Синяя** — выходной или праздник.
- **Красный OFF** — работник не вышел: больничный, отпуск, отсутствие, подтверждённый ноль; либо будний день без часов в неделе, когда работник работал у этого заказчика, начиная с его первого рабочего дня месяца. Сегодняшний и будущие дни OFF не бывают.
- **Жёлтая рамка** — неделя ещё не отправлена работником.

### 1.4 Excel
«Скачать Excel» под таблицей. Файл на английском (он для заказчика), с теми же цветами. Часы записаны числами, итоги — формулами SUM. Аудит: `REPORT_EXPORTED / CUSTOMER_MONTH_MATRIX`.

## 2. Перенос часов другому заказчику
Кнопка «⇄» в строке таблицы Табеля v2. Используется, когда работник отмечался не у того заказчика (например, «без заказчика» вместо Aros Marine).

Можно выбрать дни и другого заказчика того же объекта (или «Без заказчика»). Окно показывает итог: «Будет перенесено N ч…». Время прихода, ухода и перерывы не меняются.

Код: `lib/move-hours-to-customer.ts`, API `POST /api/admin/timesheets-v2/move-hours` (`preview: true` — только посчитать).

- **Переносятся автоматически** только недели, где табель ещё в статусе `DRAFT` или `RETURNED`. Отправленные и утверждённые недели не переписываются: ответ `409 TIMESHEET_SUBMITTED` с датами — такие дни исправляются штатной корректировкой.
- **Если на эти дни нет назначения к целевому заказчику**, оно создаётся только на нужные дни: неосновное, без возможности отметиться (`clockInDisabledAt`), с тем же шаблоном. Без этого отрезок табеля не может ссылаться на назначение.
- **Часы из отметок** переносятся через `applyClockShiftFragmentReasonEdit`: остаётся запись в `ClockShiftAdjustment`, и при пересинхронизации перенос не теряется. Вручную введённые отрезки переносятся напрямую.
- **Аудит:** `HOURS_MOVED_TO_CUSTOMER` (дни, отрезки, минуты, созданные назначения).
- **Утверждения заказчика** по затронутым неделям сами становятся «изменено после утверждения» (по отпечатку). Остальное не трогается.

## 3. Перевод работника
- **Одно место работы.** В интерфейсе больше нет «основное / неосновное».
  - Новое назначение и место после перевода автоматически становятся основными. Поле `isPrimary` осталось внутри системы для логики табеля.
  - Переключатель «Сделать основным / Снять статус» удалён.
  - Форма «Новое назначение» не создаёт второе параллельное место. Если место уже есть, она отправляет в карточку работника.
- **Карточка работника → «Перевести / изменить место работы»:**
  - поля: объект, заказчик, график; когда — «Сегодня» (по умолчанию), «Завтра» или своя дата;
  - сводка «что изменится» подгружается сама, подтверждение одной кнопкой;
  - уже записанные часы остаются на прежнем месте, новые идут на новое.
- **Открытая смена.** Как и раньше, форма спрашивает: «доработать сегодня на текущем объекте» или «перенести и сегодняшнюю смену».
- **Исправление на месте** (дизайн R15 §3.4).
  - **Когда:** назначение начинается сегодня (или позже), и по нему ещё ничего не записано — нет отметки, открытой смены, фрагментов, отрезков табеля, отправленных строк или корректировок.
  - **Что происходит:** «перевод с сегодня» исправляет то же назначение — объект, заказчика, шаблон. Плановые смены пересобираются. Записываются `AssignmentTransition` (from = to) и `ASSIGNMENT_CORRECTED`.
  - **Если назначение уже использовано:** `409 ASSIGNMENT_STARTED_IN_USE` с подсказкой выбрать «Завтра».
  - **Код:** `correctUnusedAssignment` в `lib/assignment-lifecycle-service.ts`.

## 3a. Возврат снятого места и простое завершение (2026-10-15, после звонка заказчика)
- **«Добавить объект»** (или перевод), чьи даты пересекаются **только с одним снятым** назначением того же объекта и заказчика, не отказывает (раньше EX-02 давал `ASSIGNMENT_OVERLAP`). Вместо этого снятое назначение возвращается:
  - снимается `clockInDisabledAt`;
  - даты расширяются до запрошенных;
  - применяется выбранный график, а если график не выбран — сохраняется прежний;
  - назначение становится основным;
  - незанятые плановые смены пересобираются, уже записанные часы остаются на нём;
  - записывается `ASSIGNMENT_REACTIVATED` и переход.
- Если по пути стоят два и более назначения того же заказчика — по-прежнему `ASSIGNMENT_OVERLAP`.
- Код: `findReactivatableAssignment` / `reactivateRemovedAssignmentInTx` в `lib/assignments.ts`; `changeWorkplaceInTx(reactivateAssignmentId)`.
- **Причина при завершении или снятии необязательна** — и в API (`/end`), и в формах.
- **Список «Назначения»:**
  - колонка «Статус»: Действует / Запланировано / Снято / Завершено;
  - кнопка «Завершить» только у действующих и запланированных;
  - дата окончания по умолчанию не раньше даты начала.
- **Карточка работника без текущего места** прямо говорит, что делать: выбрать объект, заказчика и график в «Добавить объект». Действует с сегодня, прежнее назначение просто вернётся.
