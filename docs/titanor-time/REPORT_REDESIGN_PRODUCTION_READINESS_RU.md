## 4. Как исправлен каждый дефект

- **D1 (§2) — URL источник истины.** `app/admin/reports/page.tsx` разбирает `view` (`overview|worker|site|files`), `periodId`, `employeeId`, `siteId`, `page`, `filesPage`. `view=worker` игнорирует `siteId`, `view=site` игнорирует `employeeId` → конфликт двух сущностей структурно невозможен. `view=worker` без `employeeId` → экран выбора работника; `view=site` без `siteId` → экран выбора объекта. Неизвестный/битый id → понятное сообщение (`period-invalid`, `period-not-found`, `entity-invalid`, `entity-not-found`), никогда молчаливой подмены. Ссылки вкладок «По работнику»/«По объекту» никогда не несут id противоположной сущности. `Reset` → чистый `/admin/reports`. Back/Forward/reload восстанавливают экран (всё в URL, страница `force-dynamic`).
- **D2 (§3) — тихое обрезание.** `getPeriodTimeReport` / `getSiteTimeReport` получили режим `{ all: true }` — полный набор строк в той же `RepeatableRead`-транзакции, что считает сводку. Экспорт использует его → строка `TOTAL` по суммируемым колонкам (gross / paid-break / unpaid-break / worked minutes / segments) равна сумме строк выше. UI-списки (объекты периода, работники объекта, история файлов) теперь реально пагинируются (`page`/`filesPage` в URL), с показом «Showing N–M of T · page P of TP». Уникальные работники / дни рассчитываются отдельно и помечены в файле и UI как дедуплицированные компанейские значения, не сумма колонок (§3.10).
- **D3 (§6) — язык.** Новый `lib/reporting/working-report.ts` + `period/site/worker` CSV+PDF билдеры — только английский (заголовок, колонки, статусы, единицы, подписи, итоги, пустые состояния, номера страниц). Баннер `WORKING REPORT — NOT AN OFFICIAL PAYROLL EXPORT` + метаблок (report type, payroll period, period status, generated at, generated by, included filters) в каждом файле.
- **D4 (§7) — ReportFile.** Additive-миграция `20260906210000_harden_report_files` (см. `05_RAW_SQL_REGISTER.md` §17): FK-18/FK-19, CK-52..CK-58. `lib/report-files.ts`: пагинация вместо `take:100`, валидация до записи, аудит `REPORT_FILE_CREATED`/`REPORT_FILE_DELETED` в одной транзакции с записью, `verifyReportFileIntegrity` (пересчёт SHA-256 перед выдачей). `lib/reporting/content-disposition.ts` — RFC 6266 `filename` + `filename*`. Предел размера — 25 MiB (`REPORT_FILE_MAX_BYTES` + CK-55), документирован.
  - **Аудит скачивания — решение: НЕ добавляем.** Скачивания read-only, частые (повторное скачивание после reload, несколько админов) и залили бы `AuditEvent`. Значимый жизненный цикл покрыт `REPORT_FILE_CREATED` / `REPORT_FILE_DELETED`. Соответствует существующей политике (`admin.notification.dismiss` — «не критичное admin mutation, не требует audit»).
  - **Удаление физическое** (§7.12), но факт удаления с метаданными (не байтами) остаётся в `AuditEvent`.
- **D5 (§8) — идемпотентность.** `POST /api/admin/reports/export` требует `Idempotency-Key` (переиспользует `lib/idempotency.ts` + таблицу `IdempotencyKey`, тот же паттерн, что официальный `POST /api/admin/periods/:periodId/export`). Повтор того же запроса → тот же файл; новый ключ → новый снимок; тот же ключ + другое тело → `409 IDEMPOTENCY_KEY_REUSED`; параллельные одинаковые → один создаёт, второй получает cached или `409 IN_PROGRESS`. Клиент генерирует свежий UUID на каждый осознанный клик, переиспользует его при retry-после-ошибки, сбрасывает после успеха.
- **D6 (§9) — честные ошибки.** `ReportFileDeleteButton`: проверяет `response.ok`, читает нормализованную ошибку, показывает её, оставляет кнопку доступной, не имитирует успех, refresh только при реальном успехе. `ReportExportControls`: блокировка кнопок на время запроса, генерация/переиспользование idempotency-key, отдельная кнопка «Повторить» с сохранением формата упавшего запроса.
- **D7 (§4) — старый дизайн.** Выбор дизайна хранится в отдельном cookie `titanor-admin-design` (не сессионный) → рендерится на сервере в `app/admin/layout.tsx` (нет вспышки). `classic` → тот же самый до-редизайн-разметка (`admin-shell > admin-header > brand/identity/actions`, `AdminNav`, `admin-content`) + тумблер внутри `admin-header-actions`. `modern` → `AdminModernShell` (client, только для мобильного меню: Escape закрывает, фокус возвращается на триггер, backdrop; активный пункт по `usePathname` + `aria-current`). `AdminDesignToggle` локализован (RU «Новый вид»/«Старый вид», EN «New view»/«Classic view»), зеркалит в `localStorage` в `try/catch`, битое значение сбрасывает. `AdminDesignFrame.tsx` удалён.
- **D8 (§5) — рабочий vs официальный.** Блок `.report-working-notice` обычным языком: «Это аналитический снимок… можно создать при любом статусе периода, сохранить, скачать повторно и удалить. Не заменяет официальную payroll-выгрузку.» + ссылка «Перейти к официальной payroll-выгрузке» (`/admin/export`); для `OPEN` добавляется «Для официальной payroll-выгрузки период нужно сначала заблокировать.» Официальный `/admin/export`, `ExportBatch`/`ExportItem` и правила блокировки периода **не тронуты**.

## 11. Матрица ADMIN / SUPER_ADMIN

Новых permission-кодов нет. `POST /api/admin/reports/export` требует одновременно
`period.read.all` + `site.read.all` + `worker.read.all` + `timesheet.read.all` + `export.read` +
`export.create`. Download — `export.read`. DELETE — `export.create` (+ CSRF `X-Requested-With`).

| Роль | Список/обзор | Создать | Скачать | Удалить |
|---|---|---|---|---|
| `ADMIN` | да | да | да | да |
| `SUPER_ADMIN` | да | да | да | да |
| `export.read` без `export.create` | да | **403** | да | **403** |
| без прав / чужая роль | 403 | 403 | 403 | 403 |
| без сессии | 401 | 401 | 401 | 401 |
| без `X-Requested-With` (POST/DELETE) | — | 403 | — | 403 |

ADMIN и SUPER_ADMIN имеют **одинаковые** возможности в этом разделе (как и во всём операционном
слое — `02_ROLE_PERMISSION_MATRIX.md`). Матрица ролей не менялась. Проверено
`_test-report-files-api.ts` checks 4a–4h.

## 16. Оставшиеся ограничения и риски

- `getPeriodTimeReport({ all: true })` держит весь набор объектов в памяти одной транзакции —
  для компании такого масштаба (десятки–сотни объектов) это несколько КБ, но это «весь набор»,
  не потоковая выдача. Для реалистичных объёмов Titanor приемлемо.
- Idempotency при сбое между `createReportFile` и `completeIdempotentRequest`: строка `ReportFile`
  создана, ключ остаётся `PROCESSING` до TTL 24ч → повторный запрос с тем же ключом получает
  `409 IN_PROGRESS` до истечения TTL. Это существующее поведение инфраструктуры `lib/idempotency.ts`
  (то же у официального экспорта), не регресс.
- Пагинация фильтр-дропдаунов (`listPeriodOptions` — cap 50, `listSiteOptionsForAdmin` /
  `listEmployeesForReportSelect` — все строки) не изменена: это существующие лоадеры,
  используемые и другими страницами; §3 требует пагинацию **таблиц отчётов**, не селектов.
- «Старый вид» на mobile выглядит так же, как выглядел до редизайна (горизонтальный `admin-nav`
  подрезается на узком экране) — это исходное поведение классической оболочки, не регресс:
  оболочка восстановлена байт-в-байт. Новый дизайн на mobile — с боковым меню и без подреза.
- Полный browser lane (21 прочий тест) не прогонялся в этой сессии — по манифесту репозитория это
  «pilot acceptance / R12», не CI-gate, и требует выделенного harness с fresh-DB на каждый тест.
  Перед слиянием стоит прогнать его целиком (стандартная pre-merge проверка).
- Ошибочные сообщения бэкенда локализованы по `code`; редкий неизвестный `code` даёт общий
  локализованный текст, никогда не сырую строку.
