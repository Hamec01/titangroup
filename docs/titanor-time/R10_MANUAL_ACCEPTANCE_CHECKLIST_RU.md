  restore 13/13, миграции 98/0, 0 CVE, `_test-t9-role-matrix` 32/0) — см. `R10_PILOT_ACCEPTANCE_REPORT_RU.md`.
- **Где:** пилот `t97-pilot-edd950c` — `https://t97-dd686bc3d4.84.247.130.242.nip.io` (или `127.0.0.1:3297`).
  **Не production.** Тестовые действия оставляют данные в pilot DB — это нормально.
- **Отмечать:** ☑ / ✗ + короткая заметка. Провалы → в отчёт как P0/P1 (блокер) или P2 (backlog).
- **Дубли не делать** с `R09_BROWSER_ACCEPTANCE_RU.md` (R09-специфика: /admin/users, denial-тексты,
  doc-attention карточка, overflow, clock split, worker-card nav) — это отдельный чек-лист по R09.

## Как оформить результат

Провалы: **P0** (нельзя выпускать) / **P1** (нужно поправить до cutover) → в
`R10_PILOT_ACCEPTANCE_REPORT_RU.md`, каждое исправление = новый кандидат + повтор затронутых
тестов. **P2** (косметика / backlog) → список в отчёте, выпуск не блокируют.

После прохождения A–F без открытых P0/P1 — **подтвердить pilot acceptance** (ТЗ §22): это
разблокирует R11 (домен/Caddy).
