## 1. Приложение Titanor Time (app.titanorgroup.fi)

| пункт | решение |
|---|---|
| Языки интерфейса | **только RU + EN** |
| Финский интерфейс | **не нужен** — отдельный FI UI не делаем и не поддерживаем |
| Дефолт | `RU` (`DEFAULT_APP_LOCALE`), переключение — `EN` |
| Финский в приложении | допустим **только в экспортируемых документах** (позже, если понадобится); в самом UI — нет |
| Legacy `FI` | значение `User.locale = 'FI'` — устаревшее; приложение сворачивает его в `RU` (`normalizeToAppLocale`). Специально не удаляем, но новым аккаунтам не ставим |

**Как это уже устроено в коде (проверено):**

- `titanor-time-app/lib/i18n/locale.ts`: `AppLocale = 'EN' | 'RU'`; `DEFAULT_APP_LOCALE = 'RU'`;
  `normalizeToAppLocale` сворачивает `FI → RU`.
- Prisma-энум `Locale { FI EN RU }` содержит `FI` только для обратной совместимости.
- `<html lang>` в приложении ставится по `AppLocale`: `RU → "ru"`, `EN → "en"`
  (`AppLocaleProvider`, эффект). Офлайн-оболочка — читатель (`persist={false}`), не перезаписывает
  сохранённый выбор (фикс `ef5548b`, регрессия `_test-offline-shell-locale.ts` RU/EN + legacy FI→RU).

**Вывод:** приложение уже соответствует модели. Изменений кода на R14 не требуется.

## 2. Публичный сайт titanorgroup.fi

| пункт | решение |
|---|---|
| Языки | **только FI + EN** |
| Русский | **нет** — на публичном сайте русского языка быть не должно |
| Дефолт | `EN` (`app/i18n.ts` `defaultLocale = 'en'`; `/` → 307 → `/en`) |
| `/fi` | финский контент **и** `<html lang="fi">` |
| `/en` | английский контент и `<html lang="en">` |

**Проверено на живом сайте 2026-08-31:**

- `app/i18n.ts`: `locales = ['fi', 'en']`, `defaultLocale = 'en'`. Русских строк в `app/**` нет
  (Cyrillic-скан — пусто). Изначально сайт был `fi/en/ru`, русский убран ещё в ранних коммитах.
- `GET /` → `307 → /en`. ✅
- `/en` → контент EN, `<html lang="en">`. ✅
- `/fi` → контент FI (Etusivu / Palvelut / Yhteystiedot / «Ota yhteyttä» / Laivanrakennus). ✅
  **`<html lang="en">` — НЕ соответствует модели (должно быть `lang="fi"`).** ❌

### 2.1 Единственный разрыв — `<html lang>` на `/fi`

**Причина:** в App Router тег `<html>` рендерит только корневой layout `app/layout.tsx`, где
`lang="en"` захардкожен. Сегмент `app/[lang]/` вложен ниже и не может переопределить `<html>`.

**Это не регрессия этой задачи** — известный i18n-backlog (`NEXT_AGENT_HANDOFF_RU.md` §7).

**Минимальный фикс (готов к применению, НЕ применён — публичный сайт заморожен до отдельного
разрешения):**

- в `app/[lang]/layout.tsx` рендерить маленький клиентский компонент, который в эффекте делает
  `document.documentElement.lang = lang` (тот же приём, что `AppLocaleProvider` в приложении).
  SSR отдаст `en`, клиент поправит на `fi` при гидрации. Правки контента не нужны — FI-контент
  уже корректен.
- Для SSR-корректного `lang` (лучше для SEO) — вариант побольше: поднять `[lang]` в корень
  роутинга; на R14 не трогаем.
- Деплой — только через `ops/site/deploy-site-<sha>.sh` (по образцу `deploy-site-r07b.sh`),
  в maintenance-окне или отдельным согласованным деплоем сайта.

**Решение для владельца:** фиксить `/fi` `lang` **до R14**, **вместе с R14** (публикация
Employee-login ссылки — всё равно деплой сайта) или **после R14** — на выбор. Технический
релиз Titanor Time это не блокирует.
