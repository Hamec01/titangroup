## 0. Как GPS работал ДО этой работы (снимок 2026-08-28, до шагов 1–4)

> Это исходный снимок для контекста. Что изменилось — см. ЖУРНАЛ выше. Кратко: LOW_ACCURACY
> исключение теперь несёт расстояние до объекта + карту (шаг 1); `watchPosition` + разрешение один
> раз + лучший-fix-за-окно (шаги 2–3); порог 75 м вынесен в `CompanyAttendancePolicy` (шаг 4).

- **`lib/worker-gps.ts` `captureGpsSnapshot()`** — один-единственный `navigator.geolocation
  .getCurrentPosition(..., { enableHighAccuracy: true, timeout: 12000, maximumAge: 0 })`. **Никогда
  не `watchPosition`** (осознанное решение — privacy-комментарий в коде). `navigator.permissions`
  не используется.
- Вызывается: на Check In / Check Out / Switch Site, и раз в 30 с (`ZONE_CHECK_INTERVAL_MS`) для
  бейджа «в зоне» пока вкладка видима.
- **Серверный порог точности: `MAX_ACCEPTABLE_ACCURACY_METERS = 75`** (`lib/attendance-clock.ts`).
  `accuracy > 75 м` → `gpsVerification = NOT_VERIFIED`, `reason = LOW_ACCURACY` → создаётся
  `AttendanceException(GPS_NOT_VERIFIED)`. Порог **захардкожен**, не в `CompanyAttendancePolicy`.
- Check In **не блокируется** плохой точностью — событие принимается (`processingState: ACCEPTED`),
  смена открывается, но админу падает исключение. Это и есть кейс Sadovnikov (accuracy 2000 м).
- **Сырые координаты СОХРАНЯЮТСЯ** даже при `LOW_ACCURACY** — `ClockEventLocation(latitude,
  longitude)` пишется и в онлайне, и в offline-синхронизации (`lib/attendance-sync.ts`), когда
  `gpsResult.location` не null (а при LOW_ACCURACY он не null — `evaluateGpsReading` возвращает
  координаты).
- **НО** `exceptionDetailForGps()` формирует `detail` только для `VERIFIED_OUTSIDE`
  (distance/accuracy/threshold). Для `LOW_ACCURACY` `detail = null` → в карточке исключения
  (`ExceptionDetailView`) админ видит только «Точность GPS: 2000 м» и пустой detail — **ни
  координат, ни расстояния до объекта, ни карты**.
- Карта GPS-точек работника есть: `/admin/workers/[id]/locations` (MapLibre/OpenFreeMap,
  `WorkerLocationMap`), но за **отдельным строгим правом `attendance.gps.read.raw`** и **не
  прилинкована** из карточки исключения.
- Offline outbox (`lib/offline-outbox/outbox.ts`) хранит одну GPS-точку (`OutboxGps`), снятую в
  момент нажатия. Тренда точности / лучшей за окно нет.

## 1. Задача 1 — разрешение GPS один раз

**Что просит владелец:** «человек соглашается 1 раз, и приложение имеет право отслеживать».

**Почему сейчас переспрашивает.** Само веб-приложение НЕ вызывает повторный prompt — браузер
помнит грант на origin. Переспрашивает **ОС**:
- iOS Safari: prompt «Разрешить один раз / Разрешить при использовании / Запретить». Если работник
  жмёт «один раз» — каждая новая сессия спрашивает снова. Для PWA с домашнего экрана — отдельное
  состояние права.
- Android Chrome: «Только в этот раз» (Android 12+) — то же самое.

**Что можно сделать (веб-возможности):**

1. **Явный экран-объяснение при первом входе** + одна кнопка «Разрешить геолокацию». Текст:
   *«Выберите “Разрешить при использовании приложения” (не “Один раз”) — тогда приложение больше не
   будет спрашивать»*. + скриншоты для iOS/Android. Дублировать в `/guide`.
2. **`navigator.permissions.query({ name: 'geolocation' })`** — приложение видит состояние
   (`granted` / `prompt` / `denied`) и: не дёргает geolocation зря; при `denied` показывает
   инструкцию «как включить в настройках»; при `granted` — молчит.
3. **Один долгоживущий `watchPosition`** вместо периодических `getCurrentPosition`. Пока приложение
   открыто — одна подписка: ОС держит один сеанс права, координаты приходят сами, повторных
   запросов нет. Это же резко улучшает точность (см. задачу 2). **Требует пересмотра
   privacy-решения «только one-shot»** — владелец его явно запросил; фиксируем в дизайн-доке как
   осознанное изменение, координаты по-прежнему не логируются и не кладутся в localStorage.
4. **Онбординг права при активации** — просить геолокацию сразу после установки PWA / первого
   входа, а не при первом Check In (когда работник спешит).

**Оценка:** 1–2 дня (permissions API + watchPosition + экран онбординга + тексты). Без миграции.

## 2. Задача 2 — надёжность координат (в т.ч. offline)

**Кейс Sadovnikov:** accuracy 2000 м → координата по вышкам/Wi-Fi, GPS не успел взять fix (внутри
цеха Meyer Turku Shipyard). Событие снято offline, потом синхронизировано. Система честно не смогла
подтвердить геозону.

**Что можно сделать:**

### 2a. Брать лучший fix, а не первый (клиент)
- **`watchPosition` с окном прогрева.** Когда открыт экран Check In — подписка на позицию. GPS
  обычно улучшается 2000 м → 20–50 м за 10–30 с на улице. В момент нажатия использовать **лучшую
  (минимальный `accuracy`) точку за последние ~60 с**, не мгновенную.
- **Ретрай в `captureGpsSnapshot`.** Если первый fix `accuracy > порога` — продолжать до ~25–30 с,
  вернуть лучший. Сейчас timeout 12 с и один fix.
- **Показать работнику точность + кнопку «Уточнить».** Перед Check In: «Точность ±2000 м — выйдите
  на улицу и нажмите Обновить». Check In всё равно не блокировать (как сейчас), но дать шанс
  улучшить.
- Offline: та же логика — outbox сохраняет лучшую точку окна + тренд точности, а не мгновенную.

### 2b. Дать админу увидеть, откуда это было (сервер + UI)
- **`exceptionDetailForGps()` — заполнять detail и для `LOW_ACCURACY`:**
  `{ accuracyMeters, distanceToSiteCenterMeters (Haversine от сохранённой координаты до центра
  геозоны), geofenceRadiusMeters, coordsAvailable: true }`. Тогда админ видит: *«±2000 м, но центр
  в 280 м от объекта»* → уверенно закрывает, против *«центр в 40 км»* → реальная проблема.
- **Мини-карта в карточке исключения** (`ExceptionDetailView`): точка + круг точности + геозона
  объекта. Переиспользовать `WorkerLocationMap` / статичный тайл OpenFreeMap.
- **Ссылка «→ все GPS-точки работника»** из карточки исключения на `/admin/workers/[id]/locations`.
- **Право.** Сейчас карта за `attendance.gps.read.raw` (нет у пилотных админов). Либо выдать это
  право трём админам пилота, либо показывать в контексте исключения огрублённую карту без
  отдельного права (админ, разрешающий исключение, обязан видеть примерное место).

### 2c. Настраиваемый порог
- **`CompanyAttendancePolicy.maxGpsAccuracyMeters`** (новое поле, дефолт 75) — **1 миграция**.
  Большой судоверфь со слабым сигналом → владелец может поднять до 150–200 м осознанно, вместо
  правки константы в коде. Экран `/admin/attendance/policy` уже есть.

### 2d. Резолюция кейса «внутри геозоны, но точность плохая»
- Новое действие в резолюции `GPS_NOT_VERIFIED`: **«Подтвердить по координате»** — если сохранённая
  (пусть неточная) координата попадает в геозону с запасом, дать админу закрыть одним кликом с
  пометкой `resolvedByCoordinate`. Сейчас доступные действия — только dismiss / acknowledge.

**Оценка:** 3–5 дней всего (2a клиент ~1.5, 2b сервер+UI ~1.5, 2c ~0.5, 2d ~0.5).
